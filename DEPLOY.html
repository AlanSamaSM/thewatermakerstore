0 Arquitectura

Todo vive en Cloudflare, el código en GitHub, el blog se edita desde un panel web.

GitHub (repo privado)
    │
    │  git push → auto-deploy
    ▼
Cloudflare Pages  ─────────── sirve index.html, uploads/, content/
    │
    ├─ /admin/             ── Decap CMS (panel visual del blog)
    │
    └─ fetch('/api/reviews') ───► Cloudflare Worker ──► Google Places API
                                  (filtra solo 5★, cachea 1h)
  • GitHub — fuente de verdad. Cada push dispara deploy automático.
  • Cloudflare Pages — hosting estático con CDN global gratis.
  • Decap CMS — panel de edición en /admin/, guarda los posts en el mismo repo.
  • Cloudflare Worker — proxy que llama Google Places API, filtra solo reviews de 5 estrellas, cachea 1 hora.

1 Preparar código y subir a GitHub

Convertir la carpeta local en un repo de Git y empujarlo a GitHub.

1.1 Crear el repo en GitHub

  1. Entra a github.com/new
  2. Nombre: thewatermakerstore (o el que prefieras)
  3. Visibilidad: Privado (recomendado)
  4. No agregues README, .gitignore ni licencia — lo haremos localmente
  5. Click en Create repository

1.2 Preparar archivos locales

Agrega un .gitignore en la raíz del proyecto para no subir basura:

# .gitignore
.DS_Store
Thumbs.db
node_modules/
.env
.env.local
*.log
.vscode/
.idea/
.wrangler/

1.3 Inicializar git y subir

Abre una terminal en la carpeta del proyecto:

git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/TU_USUARIO/thewatermakerstore.git
git push -u origin main
Tip: Reemplaza TU_USUARIO con tu usuario real de GitHub. Si es la primera vez que haces push desde esta máquina, GitHub pedirá autenticación — usa un Personal Access Token o GitHub CLI (gh auth login).

2 Deploy a Cloudflare Pages

Conectar el repo de GitHub a Cloudflare y dejar que haga deploy automático.

2.1 Crear proyecto en Pages

  1. Entra al dashboard: dash.cloudflare.com
  2. Menú lateral → Workers & Pages
  3. Click en Create application → tab Pages → Connect to Git
  4. Autoriza Cloudflare para acceder a tu GitHub
  5. Selecciona el repo thewatermakerstore

2.2 Configurar build

Como el sitio es HTML estático puro, no hay build. Usa estos valores:

CampoValor
Project namethewatermakerstore
Production branchmain
Framework presetNone
Build command(dejar vacío)
Build output directory/

Click en Save and Deploy. En 1–2 minutos tendrás una URL tipo:

https://thewatermakerstore.pages.dev
Auto-deploy activo: De aquí en adelante, cada git push a main redesplega el sitio automáticamente.

3.5 Desplegar OAuth proxy (Cloudflare Worker)

Decap CMS necesita autenticar contra GitHub. Esto requiere un pequeño Worker OAuth:

  1. En GitHub: Settings → Developer Settings → OAuth Apps → New OAuth App
  2. Application name: Watermaker CMS
  3. Homepage URL: https://thewatermakerstore.pages.dev
  4. Authorization callback: https://decap-oauth.TU_USUARIO.workers.dev/callback
  5. Copia el Client ID y Client Secret

Despliega el Worker OAuth. Hay uno listo de la comunidad:

git clone https://github.com/sterlingwes/decap-proxy decap-oauth
cd decap-oauth
npx wrangler login
npx wrangler secret put GITHUB_CLIENT_ID
npx wrangler secret put GITHUB_CLIENT_SECRET
npx wrangler deploy
Alternativa más simple: Sveltia CMS (fork de Decap con mejor soporte Cloudflare, no requiere OAuth proxy si usas GitHub Personal Access Token). Ver docs.

3.6 Acceder al CMS

Una vez que hagas deploy, entra a:

https://thewatermakerstore.pages.dev/admin/

Inicia sesión con GitHub → ya puedes crear, editar y publicar posts desde una UI visual. Cada cambio se guarda como commit en el repo y dispara redespliegue automático.

4 Worker de Google Reviews (filtrando 5★)

Proxy que llama Google Places API, regresa solo reviews de 5 estrellas y cachea 1 hora.

4.1 Habilitar Google Places API

  1. Entra a Google Cloud Console
  2. Crea un proyecto nuevo: watermaker-reviews
  3. Busca Places API en la barra → Enable
  4. Ve a APIs & Services → Credentials → Create API Key
  5. Copia la API key (la necesitamos)
  6. Click en la key → Restrict key:
    • API restrictions → solo Places API
    • Application restrictions → None (el Worker la usa desde el servidor)

4.2 Obtener Place ID del negocio

  1. Entra a Place ID Finder
  2. Busca The Watermaker Store La Paz
  3. Copia el Place ID (empieza con ChIJ...)

4.3 Crear el Worker

En tu terminal, crea el proyecto del Worker:

npm create cloudflare@latest reviews-worker
# Selecciona: "Hello World" Worker
# TypeScript: No
# Deploy: No (lo haremos después)

cd reviews-worker

Reemplaza src/index.js con:

export default {
  async fetch(request, env, ctx) {
    // Solo aceptamos GET
    if (request.method === 'OPTIONS') {
      return new Response(null, {
        headers: {
          'Access-Control-Allow-Origin': '*',
          'Access-Control-Allow-Methods': 'GET, OPTIONS',
          'Access-Control-Max-Age': '86400'
        }
      });
    }

    // Cache edge 1 hora
    const cacheKey = new Request(request.url, request);
    const cache = caches.default;
    let response = await cache.match(cacheKey);
    if (response) return response;

    const url = new URL(
      'https://maps.googleapis.com/maps/api/place/details/json'
    );
    url.searchParams.set('place_id', env.PLACE_ID);
    url.searchParams.set('fields', 'reviews,rating,user_ratings_total,name');
    url.searchParams.set('language', 'es');
    url.searchParams.set('key', env.GOOGLE_API_KEY);

    const apiRes = await fetch(url.toString());
    const data = await apiRes.json();

    if (data.status !== 'OK') {
      return new Response(JSON.stringify({ error: data.status }), {
        status: 502,
        headers: { 'Content-Type': 'application/json', 'Access-Control-Allow-Origin': '*' }
      });
    }

    // Filtrar solo 5 estrellas
    const fiveStar = (data.result.reviews || [])
      .filter(r => r.rating === 5)
      .map(r => ({
        author: r.author_name,
        photo: r.profile_photo_url,
        rating: r.rating,
        text: r.text,
        relative_time: r.relative_time_description,
        time: r.time
      }));

    const payload = {
      business: data.result.name,
      overall_rating: data.result.rating,
      total_reviews: data.result.user_ratings_total,
      five_star_reviews: fiveStar
    };

    response = new Response(JSON.stringify(payload), {
      headers: {
        'Content-Type': 'application/json',
        'Access-Control-Allow-Origin': '*',
        'Cache-Control': 'public, max-age=3600'
      }
    });

    ctx.waitUntil(cache.put(cacheKey, response.clone()));
    return response;
  }
};

5 Conectar reviews al sitio

Reemplazar el testimonio placeholder del index.html con reviews reales del Worker.

5.1 Reemplazar el componente de testimonio

En index.html, agrega este hook junto a los otros (useScrolled, etc.):

const REVIEWS_URL = 'https://reviews-worker.TU_USUARIO.workers.dev';

function useGoogleReviews() {
  const [data, setData] = useState({ reviews: [], loading: true, error: null });
  useEffect(() => {
    fetch(REVIEWS_URL)
      .then(r => r.json())
      .then(d => setData({
        reviews: d.five_star_reviews || [],
        rating: d.overall_rating,
        total: d.total_reviews,
        loading: false,
        error: null
      }))
      .catch(err => setData({ reviews: [], loading: false, error: err.message }));
  }, []);
  return data;
}

Y reemplaza el componente de testimonio por uno que use los datos del Worker. Esto lo podemos hacer juntos en otra sesión cuando ya tengas la URL del Worker real.

5.2 Conectar el blog a content/posts.json

En index.html, reemplaza el array BLOG_POSTS hardcodeado por un fetch a /content/posts.json:

function useBlogPosts() {
  const [posts, setPosts] = useState([]);
  useEffect(() => {
    fetch('/content/posts.json')
      .then(r => r.json())
      .then(d => setPosts(d.posts || []))
      .catch(() => setPosts([]));
  }, []);
  return posts;
}
Tip: Estos dos cambios del index.html son el último paso. Puedo ayudarte a implementarlos cuando ya tengas las URLs del Worker y confirmado que el CMS funciona.

6 Dominio personalizado (cuando se libere)

Cuando thewatermakerstore.com.mx esté disponible y lo compres, conéctalo a Cloudflare.

  1. Compra el dominio (Cloudflare Registrar es el más barato y ya estás en su ecosistema)
  2. Dashboard → Workers & Pages → thewatermakerstore → Custom domains
  3. Set up a custom domain → escribe thewatermakerstore.com.mx
  4. Si ya está en Cloudflare, configura DNS automático
  5. Espera propagación (5–30 min)
  6. Actualiza en index.html todas las referencias a www.thewatermakerstore.com.mx (og:url, canonical, etc.) — ya están puestas
